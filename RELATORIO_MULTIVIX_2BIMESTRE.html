1. INTRODUÇÃO

O presente relatório acadêmico-técnico documenta o processo de concepção, refatoração e evolução funcional da aplicação web Agenda Fácil, submetida como avaliação integradora do 2º Bimestre de 2026 na disciplina de Programação para Internet do Centro Universitário Multivix, sob orientação do Prof. Me. Elionai Magalhães.

Enquanto o escopo do 1º bimestre acadêmico teve como foco o domínio da estrutura semântica (HTML5) e da estilização visual responsiva (CSS3), esta segunda etapa concentrou-se primordialmente na lógica de programação em JavaScript (ES6+), na manipulação reativa do Document Object Model (DOM), na comunicação de rede assíncrona (Fetch API com async/await) e no gerenciamento dinâmico de dados e regras de negócio.

O edital estabelece explicitamente que o uso de banco de dados e servidores back-end não é obrigatório para a avaliação, sendo permitida a utilização exclusiva de arrays/objetos em memória e localStorage. No entanto, com o objetivo de entregar uma solução de padrão profissional e demonstrar domínio completo de engenharia de software Full-Stack, o projeto foi desenvolvido com suporte nativo a uma API REST em Node.js (Express) integrada ao banco de dados relacional Microsoft SQL Server.

Para assegurar total comodidade na avaliação e garantir funcionamento em qualquer máquina sem dependência de instalação prévia de banco, a aplicação possui um sofisticado sistema de Fallback Transparente: se aberta via Live Server no VS Code (sem servidor ou banco rodando), o front-end detecta a ausência da API em tempo real e opera perfeitamente utilizando localStorage para persistência e o arquivo local servicos.json para consulta de dados.

2. DESCRIÇÃO DO PROJETO E ARQUITETURA

2.1. Visão Geral da Solução

O Agenda Fácil é uma solução moderna voltada para a gestão comercial de agendamentos em salões de beleza, estúdios de estética e barbearias. A plataforma oferece uma experiência rica e acessível tanto para os clientes quanto para a administração do salão:

  • Catálogo Interativo de Serviços: Apresentação de 10 serviços especializados (Corte, Barboterapia, Coloração, Manicure, Alongamento em Gel, Limpeza de Pele etc.), com categorização dinâmica, precificação em Reais (R$) e duração em minutos;
  • Agendamento Inteligente: Formulário reativo com máscara dinâmica de telefone, seleção de serviços e geração contextual de grade de horários disponíveis;
  • Painel de Gestão (CRUD no DOM): Tabela completa de acompanhamento com badges de status (Pendente, Confirmado, Cancelado), edição em modal com efeito backdrop blur e exclusão instantânea;
  • Métricas Financeiras em Tempo Real: Indicadores automáticos de faturamento previsto, total de agendamentos, serviço mais popular e taxa de confirmação.

2.3. Arquitetura em Três Camadas e Modo Fallback

Para assegurar a máxima resiliência e atender com excelência aos critérios avaliativos, a aplicação foi projetada para operar em três modos de execução:

  1. Modo Completo Integrado (Full-Stack): A aplicação consome a API REST Express conectada ao Microsoft SQL Server nativo (instância local na porta 1433 ou dinâmica), persistindo agendamentos e lendo serviços diretamente do banco de dados relacional.
  2. Modo Contingência Node.js (Sem SQL Server): Caso a API Express esteja em execução mas o banco SQL Server esteja desligado, a API detecta a ausência de conexão e opera em memória volátil com os serviços do arquivo JSON, sem interromper o serviço.
  3. Modo Live Server / Standalone (100% Client-Side): Caso o avaliador execute apenas a pasta public/ através do Live Server do VS Code, a função fetchServices() detecta o erro de conexão HTTP, lê com sucesso o arquivo public/data/servicos.json e armazena os agendamentos no localStorage do navegador. Desta forma, o sistema nunca trava nem apresenta tela em branco.

3.1. Base Existente: HTML5 Semântico e Responsividade

A interface foi totalmente reconstruída semântica e visualmente. Não há elementos genéricos desprovidos de significado estrutural. Utilizam-se tags de cabeçalho (<header>), barra de navegação acessível com aria-label (<nav>), área principal de conteúdo (<main>), seções temáticas (<section>) e cartões de serviço em elementos (<article>).

A camada CSS foi construída com CSS Variables, permitindo alternância instantânea entre modo escuro (Dark Mode padrão, com paleta violeta profundo e acentos púrpura/teal) e modo claro (Light Mode com excelente contraste). O layout é 100% responsivo, adaptando-se com elegância a smartphones, tablets e monitores widescreen.

3.2. Validações Aprimoradas e Regras de Negócio em JavaScript

Foram implementadas três regras de validação lógica avançadas no cliente, além de tratamento rigoroso de entradas inválidas:

  • Regra 1: Prevenção de Conflito de Horário e Duplicidade de Agenda: Ao tentar agendar, o sistema verifica se já existe outro atendimento agendado para o mesmo dia cujo intervalo de atendimento conflite com o novo horário. A fórmula implementada analisa se:
    (novoInicio < existenteFim && novoFim > existenteInicio). Se houver sobreposição, o envio é impedido e um alerta específico é exibido.
  • Regra 2: Antecedência Mínima e Conformidade de Horário Comercial: O sistema impede agendamentos para datas retroativas (no passado), bloqueia domingos (dia de folga do salão) e valida os limites de atendimento (Segunda a Sexta das 09h às 20h e Sábados das 08h às 18h). Adicionalmente, agendamentos marcados para o dia corrente exigem no mínimo 1 hora de antecedência em relação ao horário do sistema.
  • Regra 3: Compatibilidade de Campos Dependentes: A grade de horários disponíveis (seletor #timeSelect) é calculada dinamicamente com base na duração do serviço escolhido (35, 45, 60, 75 ou 90 minutos) e na data selecionada, ocultando automaticamente os horários que conflitem com agendamentos pré-existentes.
  • Validação de Entradas: Nome do cliente obrigatório com no mínimo 3 caracteres e telefone/WhatsApp com máscara interativa no padrão brasileiro (99) 99999-9999.

3.3. Gerenciamento Completo de Registros (CRUD no DOM)

O painel de controle implementa as quatro operações fundamentais diretamente sobre a árvore DOM, sem nunca recarregar a página (utilizando e.preventDefault() em todos os disparos):

  • CREATE: O envio do formulário valida os dados, persiste o registro na API/localStorage e injeta a nova linha na tabela com animação suave e notificação Toast flutuante;
  • READ: Renderização dinâmica da tabela com badges coloridos de status (verde para Confirmado, amarelo para Pendente, vermelho para Cancelado), formatação de data brasileira (DD/MM/AAAA) e valores em moeda Real (R$);
  • UPDATE: Botão de edição em cada linha que abre uma janela modal sobreposta (#editModal) com desfoque de fundo (backdrop filter blur). O modal carrega os valores atuais, permite modificações e revalida os conflitos desconsiderando o próprio registro em edição;
  • DELETE: Botão de exclusão que aciona modal de confirmação de segurança (#deleteModal), removendo imediatamente o registro da tabela e recalculando todos os totais.

3.4. Consulta Dinâmica, Filtros e Resumos Calculados

O sistema conta com recursos avançados de organização de dados:

  • Busca em Tempo Real: Campo textual com escuta contínua do evento input, filtrando instantaneamente os registros por nome do cliente ou pelo nome do serviço contratado;
  • Filtro por Status: Seletor dinâmico para isolar agendamentos Confirmados, Pendentes ou Cancelados;
  • Ordenação Dinâmica: Seletor com 4 critérios: Data mais próxima, Data mais distante, Maior valor monetário e Menor valor;
  • Cards de Resumo Calculado em Tempo Real: Quatro cartões de métricas no topo do painel atualizados a cada alteração:
    1. Total de Agendamentos Visíveis;
    2. Faturamento Previsto (R$ somatório de todos os serviços ativos);
    3. Serviço Mais Procurado (cálculo de moda estatística com contador de ocorrências);
    4. Proporção Confirmados / Pendentes.

3.5. Assincronia com Fetch API e Tratamento dos Três Estados

O catálogo de serviços é recuperado de forma assíncrona através da função fetchServices() com sintaxe moderna async/await. A interface implementa o padrão de experiência do usuário com três estados distintos:

  1. Estado de Carregamento (Loading Skeleton): Exibição de cards esqueleto com efeito de pulso cintilante enquanto os dados trafegam pela rede;
  2. Estado de Sucesso: Injeção dinâmica dos 10 serviços especializados no catálogo e no select do formulário;
  3. Estado de Erro de Rede / Falha HTTP: Exibição de card visual com ícone de erro amigável, mensagem informativa e botão funcional "Tentar Novamente".

3.6. Back-end e Banco de Dados (Microsoft SQL Server)

Como diferencial de engenharia, foi desenvolvida uma API REST em Node.js com Express e persistência no Microsoft SQL Server. O script schema.sql cria o banco de dados AgendaFacilDB com as tabelas Servicos e Agendamentos:

  • Uso rigoroso do tipo de dados NVARCHAR em todas as colunas textuais para garantia de suporte completo aos caracteres especiais e acentuação da língua portuguesa (ex.: "Finalização", "Terapia", "Sobrancelhas");
  • Tabela Agendamentos com chave estrangeira vinculada à tabela de serviços e campos de data/hora estruturados (DATE e TIME);
  • Endpoints REST padronizados: GET /api/servicos, GET /api/agendamentos, POST /api/agendamentos, PUT /api/agendamentos/:id e DELETE /api/agendamentos/:id.

5. GUIA DE INSTALAÇÃO E EXECUÇÃO

O projeto foi desenhado para facilitar ao máximo a validação pelo professor orientador, oferecendo duas alternativas de execução:

5.1. Execução Simples via Live Server (100% Offline / Standalone)

Recomendado para avaliação ágil (não requer instalação de banco de dados ou terminal):

  1. Faça o clone ou baixe os arquivos do repositório GitHub;
  2. Abra a pasta do projeto no Visual Studio Code;
  3. Clique com o botão direito no arquivo public/index.html e selecione "Open with Live Server" (ou execute no terminal o comando python -m http.server 5500);
  4. A aplicação abrirá no navegador no endereço http://127.0.0.1:5500/public/index.html;
  5. Os serviços serão lidos automaticamente de public/data/servicos.json e os agendamentos serão salvos com persistência no localStorage.

5.2. Execução Completa com API Node.js e Microsoft SQL Server

Para testar a infraestrutura completa Full-Stack:

  1. Criação do Banco: Abra o SQL Server Management Studio (SSMS), abra o arquivo server/database/schema.sql e execute (tecla F5) para criar o banco AgendaFacilDB e as tabelas com os dados iniciais;
  2. Instalação de Módulos: No terminal na pasta raiz do projeto, instale as dependências: 
    npm install
  3. Configuração do Arquivo .env: Renomeie o arquivo .env.example para .env e insira as credenciais de autenticação do seu SQL Server: 
    DB_SERVER=127.0.0.1
DB_PORT=1433
DB_USER=sa
DB_PASSWORD=SuaSenhaForte123!
DB_DATABASE=AgendaFacilDB
PORT=3000
  4. Iniciar o Servidor: Execute no terminal: 
    npm start
  5. Acessar o Sistema: Acesse no navegador o endereço: http://localhost:3000.

7. CONCLUSÃO

O desenvolvimento do projeto Agenda Fácil proporcionou uma vivência prática indispensável na transição de páginas web estáticas para aplicações web ricas, interativas e orientadas a eventos (Single-Page Applications).

A atividade permitiu consolidar na prática os conceitos mais fundamentais do desenvolvimento para a Web: manipulação meticulosa da árvore DOM sem causar recarregamento de página, tratamento de fluxos assíncronos com a Fetch API e async/await, prevenção visual de erros antes do envio e cálculo de métricas analíticas no cliente em tempo real.

Além disso, a implementação voluntária de uma camada de API REST com Microsoft SQL Server — preservando concomitantemente a resiliência por meio de fallback para Live Server e localStorage — evidenciou a aplicação de conceitos de arquitetura limpa, tolerância a falhas e padrões profissionais de engenharia de software.

Conclui-se, portanto, que todos os requisitos qualitativos e quantitativos estabelecidos no edital do 2º Bimestre foram atendidos com êxito, resultando em uma aplicação pronta, moderna, acessível e funcional.
